# Playing card layout & visual balance

## 数値
- 共通カード中心間隔: 0.55 → 0.66（+20%）。幅0.5は維持。
  水平の端同士の隙間は0.05 → 0.16。3・4・5枚とも表示枚数で中央揃え。
- 手札中心: x=±0.31 → ±0.372。中心間隔0.62 → 0.744（+20%）。
  傾きを除く隙間は0.12 → 0.244。
- 縦位置: 共通カードz=-0.02、手札z=1.12のまま（中心間1.14）。
- カード外寸0.5×0.7、厚み0.0024、カメラ、背景、テーブル、チップは変更なし。
- 印刷領域: 全面 → 中央96%×96%。各辺2%（512×720上で左右10.24px、上下14.4px）の追加余白。
- Aの中央領域だけ1.2倍。全体縮小と合わせ従来比1.152倍（+15.2%）。
  クラブの飾りも同じ倍率。中央スート数・向きは維持。
- 2〜10とJ/Q/Kは元の配置・人物画を96%でそのまま使用。
  インデックスも一律96%で、余白と反転対称性を統一。

## 実装
素材SVGは一切変更せずCanvasTextureへの描画領域のみ調整。
同一縦横比で縮小し、Aは白い余白を含む中央領域だけ追加描画。
カード到着先を設定ファイルに分離。表示枚数が増えたときの列の再センタリングは
減衰係数10で滑らかに移動し、既存の配布時間・遅延・反転は維持。
reduced-motionでは即座に整列する。
新規画像・ライブラリ・外部通信先はなく、GPUテクスチャ解像度も従来どおり。

## 検証
変更前後を同じ1440×900、844×390、667×375で撮影。
フロップ・ターン・リバーそれぞれで手札、中央揃え、チップとの非干渉を確認。
全52枚一覧によりA/2/5/10/J/Q/Kを含む余白と人物の切れを確認。
既存の全52枚のSVG検査・デコード検査を維持。
表示枚数3/4/5の中央揃え・等間隔・テーブル内収まりと手札間隔を単体テストで追加。
67単体テスト・13ブラウザテスト・GitHub Pagesビルドを実行。
画像はdocs/screenshots/card-balance/{before,after}/に保存（ローカルQA資料）。

## 制約
モバイル検証はChromeのビューポート再現で、実機検証ではない。
絵柄やインデックスは小さい横画面では依然小さく、カメラ・外寸を維持する制約による。
既存のバンドルサイズ警告と画像ロード失敗時の白い面は今回の対象外。
