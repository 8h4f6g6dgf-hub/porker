# カード両隅の表示改善

## 調査
旧実装にも上下で同じrank/suitが渡され、translate(256,360)とrotate(PI)が適用されていた。固定のA、別カードのランク参照、誤った回転は見つからなかった。3Dで小さく斜めに投影される256×360テクスチャの細いセリフ文字と反転スートは識別しづらく、報告された見え方の原因と推定する。固定値バグを発見したとは扱わない。

## 修正
- 両隅を同じdrawIndex関数で描画。
- 解像度512×720、Canvas内は2倍スケール。3Dカード寸法とUV・配置・アニメーションは維持。
- 太めのサンセリフ文字、スートの縮小、余白の拡大でランクと区別。
- 10は幅56以内に収め、枠と重ならないようにした。
- ♥♦は赤、♠♣は黒。右下はランク・スートをまとめて180度回転。
- 背景、カメラ、テーブル、ディーラー、学習ロジックは無変更。

## 検証
- Chromeの実CanvasTexture生成を52枚すべてで実行。fillTextのランク・スート・色、変換行列、両隅の回転画素を検証。
- フォントヒンティングによる回転前後の輪郭差を許容するため、画素比較はチャネル差12超の割合4%以内。意味・色・回転行列の検証は完全一致。初回の2.5%閾値では最大3.13%の輪郭差があり、試験を修正した。
- A♥、9♥、10♥、J♥、Q♠、K♦、3♣を含む一覧を目視確認。
- 自動テスト63件、既存ブラウザ12件、追加52枚ブラウザ検証1件が成功。通常・Pagesビルド成功。
- ローカルQA画像: docs/screenshots/cards/card-deck-52.png、scene-desktop.png、scene-mobile.png。
- ブラウザ内生成のため画像ダウンロードは追加なし。表面テクスチャの画素数は4倍になり、使用中の7枚ではミップ込みで概算約10MiB（旧約3MiB）のGPU領域を使う。端末依存の文字ラスタライズ差は残る。
